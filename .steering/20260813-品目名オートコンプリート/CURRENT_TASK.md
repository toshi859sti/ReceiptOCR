# CURRENT_TASK.md

## 作業タイトル
一般レシート品目名（＝但し書き）のオートコンプリート追加

## 目的・背景
直前のセッションで店舗名オートコンプリートを追加した際、ユーザーから「商品名や
但し書きについても同様のことができるか」と要望があった。ユーザーの整理により
「商品名＝但し書き」「店舗名＝発行者」は呼び名が違うだけで同じ概念（レシートか
領収書かで呼称が変わる）と確認できたため、新規フィールドは追加せず、既存の
`GeneralReceiptItem.itemName`に店舗名と同じオートコンプリートの仕組みを適用した。

## 今回のタスク
- [x] `StoreNameAutocompleteField`を汎用の`AutocompleteTextField`にリネーム・一般化
      （`label`を`String?`化してラベルなし使用に対応、`colors`パラメータを追加して
      既存の除外時グレーアウト表示と両立）
- [x] `GeneralReceiptViewModel`に`itemNameSuggestions`を追加（既存の`itemGroups`
      〈canonicalKeyで正規化グルーピング済み・件数順〉をそのまま再利用、新規クエリなし）
- [x] `NewReceiptDialog`（新規手入力）・`ReceiptDetailDialog`（既存レシート編集）
      両方の品目名欄をオートコンプリート対応に変更
- [x] ビルド確認・実機インストール・両ダイアログでの候補表示→タップ補完の動作確認済み

## 完了条件
品目名入力欄（新規作成・既存編集の両方）で、入力中に過去の品目名（canonicalKeyで
正規化済み）から部分一致する候補がドロップダウン表示され、タップで補完できること。

## 進捗メモ
- 候補データソースは新規クエリを作らず`itemGroups`（品目別マッチング画面で既に
  使われているStateFlow）を再利用。件数の多い順で並んでいるため、頻出品目が
  優先的に候補上位に出る
- 実機確認で全角数字変換の罠に遭遇：`adb shell input text "22"`が全角「２２」に
  変換されてしまい「22#ノーマルタイプ...」にマッチしなかった。これはIME側の挙動で
  今回の実装バグではない。数字を含まない/日本語を含まないASCII文字列
  （"AutoItemXYZ"等）で改めて検証し、正しく動作することを確認した
  （[[feedback_adb_input_text_japanese]]参照）
- `AutocompleteTextField`のitem行使用箇所（`ReceiptDetailDialog`の編集モード）は
  元々ラベルなしのTextFieldだったため、`label`パラメータを省略可能に変更する必要が
  あった（空文字だとラベル用の枠だけ残って見た目が崩れるため`String?`化）
