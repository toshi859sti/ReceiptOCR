# CURRENT_TASK.md

## 作業タイトル
一般レシート店舗名のオートコンプリート追加

## 目的・背景
直前のセッションでレシート一覧に手入力での新規作成機能を追加したが、店舗名は
毎回ゼロから全文字入力する必要があった。ユーザーから「店舗や領収書発行者の情報を
リスト化して手入力を支援できないか」と要望があり、過去のレシートの店舗名実績を
使ったオートコンプリートを追加した（新規テーブルは作らず、既存データから動的に候補生成）。

- [x] 共有コンポーザブル`StoreNameAutocompleteField`を新設
      （`ExposedDropdownMenuBox`ベース、入力中に部分一致候補を最大5件表示）
- [x] `NewReceiptDialog`（新規手入力）・`ReceiptDetailDialog`（既存レシート編集）
      両方の店舗名欄をこのコンポーネントに置き換え
- [x] ビルド確認・実機インストール・両ダイアログでの候補表示→タップ補完の動作確認済み

## 完了条件
店舗名入力欄（新規作成・既存編集の両方）で、入力中に過去の店舗名から部分一致する
候補がドロップダウン表示され、タップで補完できること。

## 進捗メモ
- 候補データソースは`invoice_stores`（登録番号キャッシュ、T番号必須でPKが登録番号）
  ではなく`general_receipts.storeName`の実績を採用（ユーザー選択：登録番号なしの
  一般店舗も候補に含めたいため）
- フィルタ条件は「入力値を含み、かつ入力値と完全一致しない」もの。完全一致を除外して
  いるのは、既に確定した文字列と同じ候補が自分自身の下に表示され続けるのを防ぐため
- `ExposedDropdownMenuBox`の`expanded`はアイコンクリックではなく、
  `onValueChange`時に`true`にする方式（テキスト変更のたびに再評価、候補が0件なら
  自動的に非表示）
- 実機確認は日本語文字が`adb shell input text`で送信できない制約（デバイス側の
  NullPointerException、既知の環境依存バグ）があったため、ASCII文字列
  （"AutoTestStoreA"等）で候補データを作り検証。本番の日本語店舗名でも同じロジックが
  適用されるため機能的には問題ない

### 新たに発覚した問題・制約
実機（moto g66j 5G）で`adb shell input text`に日本語（マルチバイト文字）を渡すと
`InputShellCommand.sendText`でNullPointerExceptionが発生し失敗する。実機UI自動操作で
日本語文字列を入力する必要がある場合は、ASCII文字での代替検証や別の入力手段
（クリップボード経由等）を検討すること。
