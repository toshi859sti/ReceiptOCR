# CURRENT_TASK.md

## 作業タイトル
一般レシートの手入力での新規作成機能追加

## 目的・背景
これまで一般レシート（`GeneralReceipt`）は撮影→Gemini OCR→確認画面の経路でしか
新規作成できなかった（`GeneralReceiptListScreen`の詳細ダイアログ・
`GeneralReceiptConfirmScreen`は既存データの編集・OCR結果の確認はできるが、
撮影なしでゼロから新規のレシートを作る導線がなかった）。ユーザーから、レシートを
撮影せず手作業でゼロから作成できるようにしたいという要望があり対応した。

## 今回のタスク
- [x] `GeneralReceiptListScreen`に「＋」FABボタンを追加
- [x] `NewReceiptDialog`（新規作成ダイアログ）を実装：店舗名・日付（デフォルト今日）・
      品目名/金額の複数行入力（追加・削除可）・自動合計計算
- [x] 品目名が1件も入力されていない間は保存ボタンを無効化
- [x] 保存は既存の`viewModel.saveReceipt()`をそのまま利用（撮影経路と同じDB書き込み）
- [x] ビルド確認・実機インストール・実機での新規作成→一覧反映→詳細ダイアログ表示→
      削除までの一連の動作確認済み（テストデータは削除済み）

## 完了条件
レシート一覧画面から撮影なしでレシートを手入力作成でき、既存の一覧・詳細編集・
CSV出力・品目別マッチングなど他機能に既存レシートと同様に反映されること。

## 進捗メモ
- DBスキーマ変更なし。既存の`GeneralReceipt`/`GeneralReceiptItem`エンティティと
  `viewModel.saveReceipt()`をそのまま利用したため、Navigation.kt・
  GeneralReceiptViewModel.ktへの変更は不要だった
  （撮影経路の`pendingReceipt`/`pendingItems` StateFlowには一切触れていない）
- 新規作成ダイアログは既存の`ReceiptDetailDialog`（編集モード）とほぼ同じUIパターン
  （店舗名・日付・品目行・削除ボタン・追加ボタン・合計表示）を踏襲し、
  `EditableItem`データクラスをそのまま再利用した
- 実機確認中、adb shellのpowershell/git bash経由の座標クリックで、スクリーンショット表示
  サイズ（900x2000）と実解像度（1080x2400）の換算ミスが頻発した。以後は
  `uiautomator dump`でbounds属性から正確な座標を取得する方式に切り替えた方が確実
