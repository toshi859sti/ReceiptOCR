## 1. 背景

- 農家はレシートのほとんどを**個人のクレジットカード**で払い、家計の口座から引き落とされる。
  事業用の現金も別に管理していない。したがって仕訳はほぼすべて「**経費 / 事業主借**」になる
- スマホは支払方法の科目をすでに選べる（レシートごとの上書き → 支払方法の印字のルール → 既定の現金。契約 §4.5 の
  `genkin` / `mibarai` / `zigyounusikari`）。農家は「クレジット」「PayPay」のルールを事業主借にしている
- ところが今の契約（README §3 の表、transaction-import §5）では、クレカ・電子マネーのレシートは
  貸方が未払金でも事業主借でも **`ledgerType = Unpaid`**。未払帳は未払金の帳簿なので、
  「経費 / 事業主借」を未払帳に入れると帳簿と仕訳が食い違う
- 本番の vocabulary（`sha256:340bdb4a…850b`・2026 年度）で確認したこと：
  - `zigyounusikari`（事業主借）は `ledgerAffinity` が**空**（`genkin` は `Cash`、`mibarai` は `Unpaid`）。
    §5 の推定に任せると両方非該当で `Transfer`＋「要確認」になる
  - 振替の摘要 11 件のうち 6 件が「借方＝経費・貸方＝事業主借」：電気料金（家計より支払）・肥料購入（家計より支払）・
    農薬・農具・諸材料費・種苗費。**PC の辞書自体が「家計から払った経費は振替伝票」で持っている**
  - 一方、未払/発生（`Unpaid` × `In`）の摘要は 3 件（修理代・租税公課・諸経費）しかない。スマホが今やっている
    「現金/出金の摘要と同じ名前の未払/発生の摘要に置き換える」は、現金/出金 55 件のうち 2 件しか当たらない

## 2. 依頼 1：Receipt の `ledgerType` を貸方の科目で決める

| 貸方（支払方法）の科目 | `ledgerType` | 仕訳 |
|---|---|---|
| `ledgerAffinity == Cash`（現金） | `Cash` | 経費 / 現金 |
| `ledgerAffinity == Unpaid`（未払金） | `Unpaid` | 経費 / 未払金 |
| それ以外（事業主借など） | **`Transfer`** | 経費 / 事業主借 |

- キーの綴りは決め打ちせず、貸方の科目の `ledgerAffinity` で分ける（現金・買掛金を探すのと同じ考え方）
- 返品・値引き（金額が負）は今と同じく借方/貸方を入れ替えて正数で出す。`ledgerType` は入れ替える前の貸方で決める
- 書き換えをお願いしたい箇所：README §3 の表のレシート 2 行、transaction-import §5 の表の Receipt 2 行

## 3. 依頼 2：`Transfer` の Receipt の摘要

- 摘要の候補：`ledgerType == Transfer` かつ `debitAccountKey == 品目の経費科目` かつ `creditAccountKey == 貸方の科目`
- 候補が無ければ今までどおり `memoKey = null`・`UnmatchedMemo`
- 書き換えをお願いしたい箇所：vocabulary-snapshot §4.5 の「常に除外：`ledgerType == "Transfer"`（OCR は振替伝票を生成しない）」と、
  「帳簿」の行（`Receipt` を貸方の科目に応じて `Cash` / `Unpaid` / `Transfer` に）

## 4. 質問

- **Q1**：`ledgerType = Transfer` の行を、今の取込で振替伝票として登録できるか。できないなら、対応の見込みは
- **Q2**：今の契約どおり `Unpaid` で「経費 / 事業主借」を送った行は、PC ではどう扱われるか
  （未払帳に入るのか、要確認になるのか）。§2 に切り替えるまでの間の扱いを知りたい
- **Q3**：振替の摘要の `memoKey` を受けたとき、仕訳の税率・事業割合は摘要の借方側（`taxRate` / `businessRatio`）を
  使うという理解でよいか（非振替の摘要で `businessRatio` を摘要側から取るのと同じ扱い）
- **Q4**：農家が使う経費ごとの「家計より支払」の振替の摘要（ガソリン代・修理代・消耗品など）は、PC の摘要登録画面で
  農家が足す想定でよいか。プリセットに足す予定はあるか

## 5. 報告：この間のスマホ側の変更（契約に影響なし）

- スマホ DB v41：レシートの明細ごと・レシートごとに、あおいろの科目・摘要（明細）と支払方法の科目（レシート）を
  上書きできるようにした。出力の優先順は 上書き → 品目グループ／支払方法のルール → 既定（現金）
- 支払方法のルールの弥生の科目を null 可にした（あおいろ用に足したルールが弥生の出力を邪魔しないように）
- 通帳の摘要パターン・レシートの品目グループにも AI の科目提案を付けた。**AI が決めるのは科目だけ**で、
  摘要は農家が選ぶ（空欄のまま `UnmatchedMemo` で送ることもある）。§4.2 の「科目を先に決めて摘要を逆引き」のうち、
  逆引きは自動ではやらず、農家の選択にした
- 画面では**摘要から先に選ぶ**形にした。摘要を選ぶと科目はその摘要の相手科目になる。送る値（`accountKey` / `memoKey`）の
  組み合わせの制約は変わらない（摘要は必ず `counterAccountKey == 科目` のもの）

## 6. スマホ側の予定（§2・§3 の合意後）

- `ledgerType` を貸方の科目で決める（§2 の表）
- 支払方法のルールに当たらないときの既定の科目を、今の現金固定から選べるようにする（農家は事業主借にする）
- 品目グループの摘要は、既定の支払方法の帳簿の分類から選ぶ（事業主借なら振替の摘要から）。
  明細の個別変更では、そのレシートの支払方法の帳簿の分類から選ぶ
- 帳簿が既定と違うレシートは、今と同じく名前・税率・事業割合が同じ摘要をその帳簿から探して置き換え、無ければ摘要なしで送る
