## 1. 依頼 1：Receipt の `ledgerType`

提案の表のとおりで合意する。

| 貸方（支払方法）の科目 | `ledgerType` |
|---|---|
| `ledgerAffinity == Cash` | `Cash` |
| `ledgerAffinity == Unpaid` | `Unpaid` |
| それ以外（事業主借など） | `Transfer` |

- キーの綴りではなく `ledgerAffinity` で分ける方針に賛成
- 返品・値引きは入れ替える**前**の貸方で決める、も了解
- 貸方が預金（`Bank`）・買掛金（`AP`）になる支払方法は、今回は扱わない。Receipt は `bankSlotNo` を
  持てない（契約 §6）ので、預金の帳簿には正しく入らない。必要になったら改めて相談したい

## 2. 依頼 2：`Transfer` の Receipt の摘要

合意する。摘要の候補は
`ledgerType == "Transfer"` かつ `debitAccountKey == 品目の経費科目` かつ `creditAccountKey == 貸方の科目`。
候補が無ければ今までどおり `memoKey = null`・`UnmatchedMemo`。

PC の取込はすでにこの組み合わせを受けられる。`memoKey` は `ledgerType` を問わず当年度の摘要辞書に解決するだけで、
振替の摘要を弾く処理は無い。

## 3. Q1：`ledgerType = Transfer` の行を振替伝票に入れられるか

**入れられる。PC のコード変更は要らない。**

- 契約検証は `Transfer` を受け付ける
- 確定すると仕訳の帳簿の種類（`EntryType`）が `ledgerType` のまま `Transfer` になり、振替伝票に出る
- 税率は借方・貸方を別々に持つので、`debit.taxRate`・`credit.taxRate` がそれぞれそのまま入る
- `matchStatus = Matched` で摘要・科目が解決できれば、「要確認」を通らずにまとめて確定できる。
  `Transfer` だからといって要確認にはしない

## 4. Q2：今の契約どおり `Unpaid` で「経費 / 事業主借」を送った行

**要確認にはならず、そのまま確定できてしまう。そして確定後は日々の帳簿のどこにも出ない。**

- PC は `ledgerType` と科目の食い違いを見ていないので、`Matched` なら通常どおり確定する。
  仕訳の帳簿の種類は `Unpaid` になる
- ところが未払帳は「**未払金の科目**が付いた仕訳」を拾う。「経費 / 事業主借」には未払金が無いので、未払帳に出ない
- 振替伝票は「帳簿の種類が `Transfer` の仕訳」を拾うので、こちらにも出ない
- 総勘定元帳と決算書の数字には入る。**帳簿上は見えないのに決算には効く**ので、農家が気づけない

これは PC 側の穴でもあるので、PC にガードを入れる：

- 取込のとき、`ledgerType` の帳簿の科目（`Cash` なら現金、`Unpaid` なら未払金…）が借方にも貸方にも無い行は
  「要確認」に回し、理由を出す。確定前に農家が帳簿を選び直せるようにする
- 本番の DB に、すでにこの形で確定した仕訳がないかを確認する。あれば振替伝票に移す手当てを考える

**ガードは入れた**（§8 #2）。今の送り方のまま届いても「要確認」で止まり、登録すると振替伝票に入る。
切り替えを急がなくても帳簿は壊れないが、要確認が毎回出るので早めの切り替えをお願いしたい。

## 5. Q3：振替の摘要を受けたときの税率・事業割合

**事業割合は合っている。税率は違う。**

- **事業割合**：摘要が決まっていれば、摘要の `businessRatio`（借方側）を採る。送られてきた値は使わない。
  非振替の摘要と同じ扱い（2026-09-23 の合意・vocabulary-snapshot §4.7）。
  仕訳は事業割合を 1 つしか持てないので、振替の摘要の `creditBusinessRatio` は使わない
- **税率**：**PC は摘要から税率を採らない**。ファイルの `debit.taxRate`・`credit.taxRate` をそのまま仕訳に入れる。
  決め方は非振替と同じ（vocabulary-snapshot §4.7）：
  - `debit.taxRate` ← レシートの税率マーク → 無ければ借方科目の `defaultTaxCategory`。摘要の `taxRate` は見なくてよい
  - `credit.taxRate` ← **`null`**（事業主借に税率は付かない。プリセットの振替の摘要も、貸方が事業主借のものは
    `creditTaxRate` がすべて `null`）

## 6. Q4：「家計より支払」の振替の摘要

**農家が摘要登録画面の「振替」タブで足す想定でよい。** プリセットを足す予定は今のところない。

- 今のプリセットで「経費 / 事業主借」は 6 件（電気料金・肥料購入・農薬・農具・諸材料費・種苗費）。
  らくらく青色申告農業版の実機にあるものに合わせている
- 要確認画面から摘要を 1 件作る機能は、以前は振替の行に対応していなかった（現金出納帳・未払帳などの行だけ）。
  **振替の行でも作れるようにした**（§8 #4）。`UnmatchedMemo` の「経費 / 事業主借」のレシートから、借方・貸方の組の
  振替の摘要をその場で登録できる。次の書き出しからスマホの候補に入る
