## 1. スマホ側でやったこと

取り込んだ科目・摘要を見るだけの画面を、PC の画面（`examples/AoiroChobo_2024_screens/`）に合わせて作り直しました。

- 科目：タブは PC と同じ 資産・負債・収入・支出。資本の 6 件は 23b §4 で了承いただいた対応で振り分け
  （事業主貸→資産、事業主借・元入金・青申特別控除前の所得金額→負債、専従者給与・家計費→支出）
- 列も PC と同じ。グループ欄は `groupName` を**同じ値が続く間の先頭の行にだけ**出し、名前ありは薄緑・なしは灰色
- 課税区分の表記を PC に合わせた（`NotApplicable` を「不課税」に。以前は「対象外」と出していた）
- 摘要：上段 現金・預金・売掛・買掛・未払・振替、下段 入金／出金 等。列も PC と同じ

期首残高と空き枠は JSON に無いので出していません（出す必要もありません）。

## 2. お願い：画面のグループ名を `groupName` に入れてほしい

### 何が起きているか

2026 本番の `vocabulary.json`（`aoirochobo_vocabulary_2026_20260923_194016.json`）と 2024 検証データの画面を
並べると、画面のグループ欄には名前があるのに `groupName` が `null` の科目があります。

| PC 画面のグループ | 該当する科目（`accountKey`） | JSON の `groupName` |
|---|---|---|
| 経費 | `sozei` `syubyou` `mototiku` `hiryou` `siryou` `nougu` `nouyaku` `syozairyou` `syuuzen` `douryoku` `sagyou` `nougyou` `genka` `nidukuri` `yatoinin` `risi` `tidai` `totikairyouhi`、および `zappi` | `null` |
| (任意) 経費 | `tuusin` `sagyouitaku` `suirihi` | `null` |
| 繰入額 | `senzyuusya`（専従者給与。`ikuseihiyou` と `kasidaore` の間） | `null`（`ikuseihiyou` `kasidaore` は `"繰入額"` で出ている） |
| 資本 | `motoire` `kouzyo` | `null` |

出ているもの（`償却資産` `田畑` `特殊施設` `繰戻額` `繰入額` `普通預金`）はそのまま画面と一致しています。

### なぜスマホ側で補えないか

- 「経費」と「(任意) 経費」を見分ける手がかりが JSON にありません。2026 本番では通信費・作業委託料・水利費も
  `isSystem = true` です
- `displayOrder` の範囲から推測することはできますが、契約で「中身を解釈しない」と決めているのでやりません
- 専従者給与は `groupName` が無いため、スマホでは 繰入額 → （なし）→ 繰入額 と 3 つに割れて見えます

### お願いしたい形

- **画面のグループ欄に出している名前を、そのまま `groupName` に入れる。** 上の表の 4 種類（経費・(任意) 経費・
  繰入額・資本）で足ります。空き枠しか無いグループ（(任意) 資産・(任意) 負債・果樹・畜産物）は、行が無いので不要です
- JSON の形は変わらないので minor 扱いで構いません。`contentHash` は一度変わりますが、スマホは取り込み直すだけです
- `groupName` の意味（今は「決算書内訳のグループ名」）を「画面のグループ欄の名前」に広げることになります。
  `groupName` を別の用途に使っていて広げたくない場合は、**別のキー（例 `displayGroup`）で出してもらっても構いません**。
  どちらにするか教えてください。スマホはそれに合わせます

スマホ側は `groupName` を**表示にしか使っていません**。マッチングや科目の候補はすべて `accountKey` と
`ocrRole*` で決めているので、この変更で仕訳の結果は変わりません。

## 3. 2026-09-24 の 2 件 — 受領・対応不要

- **`displayOrder` を枠番号に（minor（4））**：スマホは `ORDER BY displayOrder` に使っているだけで、
  連番・1 始まりの前提はありません。書き出し直した `vocabulary.json` を取り込み直します
- **摘要の `name` が変わったら選好を捨てる（§4.7）**：スマホの学習は紐付けたときの `name` を一緒に持ち、
  取込時に変わっていたら外す作りなので、§4.8 と同じ挙動になっています
