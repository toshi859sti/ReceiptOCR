# OCR学習システム V3

## 概要

このアプリには、OCRの誤認識を自動的に学習し、精度を向上させるシステムが組み込まれています。
**V3では「人間の確認が唯一の真実」という原則に基づき、手動修正を最も重視するシステムに刷新されました。**

## 基本原則

### 「人間の確認が唯一の真実」

- 手動修正された補正パターンは最も信頼性が高い
- 自動学習は手動確認が得られるまでの暫定的な仕組み
- 失敗（手動で修正された）パターンは即座に信頼度を下げる

## 学習の仕組み

### 1. 3層補正構造

OCR結果の補正は以下の3層構造で行われます:

| 層 | 対象 | 説明 |
|----|------|------|
| **Layer 1** | LOCKED / 手動CONFIRMED | 無条件で適用。最も信頼性が高い |
| **Layer 2** | 自動CONFIRMED | スコア計算後、閾値以上なら適用 |
| **Layer 3** | 商品マスタ直接マッチ | マスタ名との類似度でマッチング |

### 2. 信頼度レベル（3段階）

| レベル | 説明 | 補正に使用 | 昇格条件 |
|--------|------|-----------|----------|
| **AUTO** | 自動学習された初期状態 | 条件付き | 実績蓄積後 |
| **CONFIRMED** | 信頼性が確認された | ✅ | 手動2回 or 自動条件 |
| **LOCKED** | 確定済み（変更不可） | ✅ | 手動5回 |

### 3. 昇格条件

#### AUTO → CONFIRMED

**方法A: 手動確認による昇格（推奨）**

| 条件 | 値 | 説明 |
|------|-----|------|
| 手動修正回数 | ≥ 2回 | 異なるコミットバッチで確認 |

**方法B: 自動昇格**

以下の**すべて**を満たす必要があります:

| 条件 | 値 | 説明 |
|------|-----|------|
| ヒット数 | ≥ 3回 | 同じパターンが3回以上出現 |
| 平均スコア | ≥ 90点 | 高いマッチング精度 |
| 高スコアヒット | ≥ 2回 | 85点以上で2回以上マッチ |
| 自動失敗数 | = 0 | 過去に手動修正されていない |

#### CONFIRMED → LOCKED

| 条件 | 値 |
|------|-----|
| 手動修正回数 | ≥ 5回 |

### 4. 降格・無効化メカニズム

V3では**失敗駆動型の降格システム**を採用:

| 現在のレベル | 失敗時の動作 |
|--------------|--------------|
| AUTO | 即座に無効化（isDisabled = true） |
| CONFIRMED | AUTOに降格 + autoFailCount増加 |
| LOCKED | 変更なし |

**「失敗」とは**: 自動補正が適用された後、ユーザーが手動で別の商品に修正した場合

## 100点満点スコアシステム

### スコア内訳

| 項目 | 最大点 | 説明 |
|------|--------|------|
| 文字類似度 | 60点 | 基本的なテキストマッチング |
| 先頭欠落ボーナス | 10点 | OCRで先頭が欠けやすいパターン |
| 濁点誤認識ボーナス | 5点 | 濁点の誤認識を許容 |
| 既存知識ボーナス | 15点 | 過去の学習パターンと一致 |
| 手動修正履歴ボーナス | 10点 | 過去に手動確認されたパターン |
| リスクペナルティ | -30点 | 曖昧さや競合がある場合 |

**合計: 最大100点**

### 判定閾値

| スコア | 判定 | 動作 |
|--------|------|------|
| ≥ 80点 | AUTO | 自動で補正を適用 |
| 60-79点 | NEED_CONFIRM | 確認を推奨（将来実装） |
| < 60点 | NO_MATCH | 補正なし |

## 手動修正の記録

### 記録タイミング

伝票入力画面で「決定」ボタンを押した際に、以下の条件を満たす行が学習対象となります:

1. `originalOcrName`（OCR原本）が存在する
2. `productMasterId`（商品マスタID）が設定されている
3. `originalOcrName` ≠ `productName`（変更があった）
4. 小計行・合計行ではない

### 記録内容

```
OcrVariant {
  productId: 修正先の商品マスタID
  variantText: OCR原本テキスト
  confidenceLevel: AUTO（新規）または既存レベル
  manualCorrectCount: +1
  lastManualCommitBatchId: コミットバッチID
}
```

## データベース構造

### ocr_variants テーブル

```
ocr_variants
├── id (主キー)
├── productId (商品マスタへの外部キー)
├── variantText (誤認識された生テキスト)
├── normalizedText (正規化後のテキスト)
├── confidenceLevel (AUTO/CONFIRMED/LOCKED)
├── hitCount (累積ヒット数)
├── highScoreHits (高スコアヒット数)
├── avgFinalScore (平均スコア)
├── manualCorrectCount (手動修正回数) ← V3追加
├── autoFailCount (自動失敗回数) ← V3追加
├── lastManualCommitBatchId (最終手動コミットバッチ) ← V3追加
├── firstSeenAt (初回記録日時)
├── lastSeenAt (最終確認日時)
├── source (AUTO/USER/IMPORT)
└── isDisabled (無効化フラグ)
```

### ocr_score_logs テーブル（V3新規）

スコア計算の詳細を記録し、閾値チューニングの根拠データとして活用:

```
ocr_score_logs
├── id (主キー)
├── rawOcrText (OCR生テキスト)
├── candidateProductId (候補商品ID)
├── decision (AUTO/NEED_CONFIRM/NO_MATCH)
├── totalScore (総合スコア)
├── textSimilarity (文字類似度)
├── prefixBonus (先頭欠落ボーナス)
├── dakutenBonus (濁点誤認識ボーナス)
├── variantBonus (既存知識ボーナス)
├── historyBonus (手動修正履歴ボーナス)
├── riskPenalty (リスクペナルティ)
├── gapToSecond (2位との差分)
├── manualOverride (後で手動修正されたか)
├── manualCorrectedProductId (手動修正後の商品ID)
├── commitBatchId (コミットバッチID)
└── createdAt (作成日時)
```

## 補正フロー

```
OCR結果
   ↓
正規化（濁点分離、記号除去）
   ↓
Layer 1: LOCKED/手動CONFIRMED検索
   ├─ 見つかった → 即座に補正適用（スコア計算なし）
   └─ 見つからない ↓
                    ↓
Layer 2: 自動CONFIRMED検索
   ├─ スコア計算 → 閾値以上なら適用
   └─ 該当なし/閾値未満 ↓
                         ↓
Layer 3: 商品マスタ直接マッチング
   ├─ スコア計算
   └─ 閾値判定（80点以上 → AUTO適用）
                    ↓
               スコアログ記録
```

## 学習状況の確認

アプリの「設定」→「OCR学習状況」から、現在のデータベース状態を確認できます。

### 表示内容

- **総パターン数**: 記録されている誤認識パターンの総数
- **信頼度レベル別**: AUTO / CONFIRMED / LOCKED の件数
- **手動修正統計**: 手動修正回数、失敗回数
- **スコア分布**: AUTO判定の修正率（閾値チューニング用）

## FAQ

### Q: なぜ手動修正を重視するの？

A: OCRの誤認識パターンは多様で、自動判定だけでは誤学習のリスクがあります。人間が「これは正しい」と確認したパターンのみを信頼することで、学習精度を保証します。

### Q: 自動昇格は使わないほうがいい？

A: 自動昇格も有効ですが、条件が厳しく設定されています（失敗数0、高スコア複数回）。手動修正による昇格のほうが早く、確実です。

### Q: 一度無効化されたパターンは復活する？

A: 同じパターンで再度手動修正を行えば、新しいレコードとして記録されます。無効化されたパターンは別途クリーンアップ対象となります。

### Q: スコアログは何に使うの？

A: 閾値のチューニングに使用します。「AUTO判定されたが手動修正された」パターンを分析することで、閾値が適切かどうかを判断できます。
